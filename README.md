# Практическая работа №3. Настройка CI/CD
## Тема: Калькулятор для подсчета личных средств (доходы и расходы)

Данный проект представляет собой программный комплекс для ведения личных финансов (учет доходов, расходов, расчет баланса, категоризация трат) с настроенным непрерывным циклом интеграции и доставки (**CI/CD**) на базе **GitHub Actions** и продуктового сервера на ОС **Linux**.

---

## 🛠 Стек технологий

- **Язык программирования:** Python 3.11+
- **Архитектура:** Объектно-ориентированное программирование (ООП)
- **Веб-интерфейс (Production):** Flask, HTML5, CSS3, Gunicorn
- **Десктоп-интерфейс (Local):** Tkinter (согласно условию задания)
- **Тестирование:** `pytest`, `pytest-cov` (осмысленные модульные и интеграционные тесты)
- **Статический анализ кода (Линтер):** `flake8`
- **Контейнеризация:** Docker, Docker Compose
- **Платформа CI/CD:** GitHub Actions (вместо GitLab CI/CD)
- **Продуктовый контур:** Виртуальная машина Linux (Ubuntu/Debian) с **GitHub Actions Self-Hosted Runner**

## 🔄 Описание пайплайна CI/CD (`.github/workflows/ci-cd.yml`)

Пайплайн состоит из 4 последовательных этапов:

1. **`Linter (Flake8)`** — проверяет исходный код на соблюдение стандартов PEP 8, отсутствие неиспользуемых импортов и синтаксических ошибок.
2. **`Unit Tests (pytest)`** — автоматически прогоняет 21 осмысленный тест (проверка граничных значений, запрет отрицательных сумм, корректность расчета баланса, сохранение в JSON, эндпоинты `/health` и добавления операций).
3. **`Docker Build`** — тестирует автоматическую сборку легковесного Docker-образа приложения.
4. **`Deploy to Production`** — запускается **только при коммите/пуше в ветку `main`** и только если все предыдущие шаги прошли успешно. Запускается непосредственно на **Self-Hosted Runner'е** в виртуальной машине Linux, обновляет контейнер или сервис и проверяет статус через `/health`.

### ШАГ 2. Подготовка продуктового контура (Linux VM)

В качестве сервера используется виртуальная машина с Linux (например, Ubuntu 22.04 / 24.04 в VirtualBox, VMware, Hyper-V, WSL2 или облаке).

1. Обновите пакеты на сервере:
   ```bash
   sudo apt update && sudo apt upgrade -y
   ```
2. Установите Docker и Docker Compose (рекомендуется для усложненной версии):
   ```bash
   sudo apt install -y docker.io docker-compose-v2 curl git
   sudo usermod -aG docker $USER
   newgrp docker
   ```
   *(Либо, если без Docker, установите `python3-pip`, `python3-venv`).*

### ШАГ 3. Подключение GitHub Actions Runner к вашей Linux VM

Это ключевой пункт задания: настройка раннера на продуктовом контуре.

1. Откройте ваш репозиторий на GitHub в браузере.
2. Перейдите во вкладку: **Settings** ➡️ **Actions** ➡️ **Runners**.
3. Нажмите зеленую кнопку **«New self-hosted runner»**.
4. Выберите:
   - **Runner image:** Linux
   - **Architecture:** x64
5. GitHub сгенерирует готовые команды для терминала вашей виртуальной машины. Скопируйте и выполните их в терминале Linux VM:

   ```bash
   # Создаем директорию для раннера
   mkdir actions-runner && cd actions-runner

   # Скачиваем архив раннера (версия может быть новее, берите ссылку из GitHub)
   curl -o actions-runner-linux-x64.tar.gz -L https://github.com/actions/runner/releases/download/v2.322.0/actions-runner-linux-x64-2.322.0.tar.gz

   # Распаковываем
   tar xzf ./actions-runner-linux-x64.tar.gz

   # Конфигурируем раннер (токен подставится автоматически на GitHub):
   ./config.sh --url https://github.com/<ВАШ_ЛОГИН>/<ВАШ_РЕПО> --token <СГЕНЕРИРОВАННЫЙ_ТОКЕН>

   # Запускаем раннер в качестве постоянной службы Linux:
   sudo ./svc.sh install
   sudo ./svc.sh start
   ```

6. Вернитесь на страницу **Settings -> Actions -> Runners** на GitHub: статус вашего раннера станет **Idle** (зеленый кружок). Сервер готов принимать поставки!

### ШАГ 4. Демонстрация работы автоматической поставки фич (Сценарий сдачи)

Преподавателю необходимо показать 3 вещи:

#### 1. Демонстрация работы калькулятора
- Откройте браузер по адресу `http://<IP-вашей-виртуалки>:5000`.
- Покажите интерфейс «Калькулятор личных средств»:
  - Добавьте доход: *Зарплата, 70 000 ₽*.
  - Добавьте расходы: *Продукты 4 500 ₽*, *Транспорт 1 200 ₽*.
  - Продемонстрируйте изменение баланса и аналитику расходов.

#### 2. Демонстрация автоматического деплоя новой фичи
- На локальном компьютере внесите изменение в код. Например, в файле `src/templates/index.html` измените заголовок или добавьте новую категорию в список `categories_income` (например, `"Кэшбэк"`).
- Сделайте коммит и отправку:
  ```bash
  git add .
  git commit -m "feat: add cashback income category and update title"
  git push origin main
  ```
- Откройте вкладку **Actions** в GitHub:
  - Покажите преподавателю, как запустился Pipeline.
  - По очереди загораются зеленые галочки: `Linter`, `Unit Tests`, `Docker Build`, `Deploy`.
- Обновите страницу `http://<IP-виртуалки>:5000` в браузере: изменения появились **без ручного вмешательства на сервере**!

#### 3. Демонстрация защиты от ошибок (Отказ деплоя при сломанных тестах)
- На локальном компьютере намеренно сломайте логику или тест. Например, измените в `src/finance_tracker.py` формулу расчета баланса: `return 999999`.
- Сделайте коммит и пуш:
  ```bash
  git commit -am "bug: intentionally broken balance calculation"
  git push origin main
  ```
- Покажите, что этап **`Unit Tests`** завершился с ошибкой (красный крестик).
- Этап **`Deploy`** был **автоматически отменен** (`cancelled / skipped`).
- На продуктовом сервере продолжает стабильно работать предыдущая корректная версия!
- Исправьте ошибку обратно и запушьте правильный код.
